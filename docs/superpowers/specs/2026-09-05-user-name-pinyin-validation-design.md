# 用户姓名拼音与用户名校验设计

## 背景与目标

用户管理表单当前先填写用户名、再填写姓名，用户名与姓名之间没有关联校验。新增和修改用户时，系统应以姓名的标准全拼作为建议用户名；当用户输入的用户名与建议值不完全一致时明确警告，但必须允许用户保留自己的输入并继续提交。

本功能只提供辅助生成和非阻断式校验，不改变用户名唯一性、长度、格式、邀请或登录规则。

## 决策

采用后端统一生成和校验的方案。后端用户插件提供唯一的姓名转拼音实现和校验接口，前端不自行实现拼音转换。创建和修改接口在保存前使用同一领域函数复核不一致情况。

这样可避免前后端拼音库及多音字规则不一致，也能使未来的其他客户端复用同一标准。

## 标准全拼规则

姓名按以下顺序规范化为建议用户名：

1. 去除姓名首尾空白。
2. 中文字符转为不带声调的小写全拼，音节之间不添加分隔符。
3. 移除姓名中的空白以及 `·`、`-` 等姓名分隔符。
4. 原有英文字母保留并转为小写。
5. 多音字采用后端拼音库的默认读音，不维护业务词典。

用户名使用精确字符串比较：只有 `username == suggested_username` 才算一致。大小写差异、下划线、分隔符和数字后缀均判定为不一致。例如，“张三”只与 `zhangsan` 一致，`ZhangSan`、`zhang_san` 和 `zhangsan1` 均触发警告。

用户可因多音字读音、组织命名规则或其他原因手动保留不一致的用户名。

## 后端设计

### 领域服务

在用户插件中增加独立的姓名拼音服务，提供两个无数据库依赖的函数：

- 根据姓名生成建议用户名。
- 根据姓名和用户名返回建议用户名及一致性结果。

API 和创建、修改流程必须调用该服务，不得重复拼音或比较逻辑。

### 校验接口

新增接口：

```http
POST /api/v1/users/validate-username-pinyin
```

请求：

```json
{
  "name": "张三",
  "username": "zhangsan"
}
```

响应数据：

```json
{
  "suggestedUsername": "zhangsan",
  "consistent": true
}
```

请求字段沿用用户新增和修改表单中姓名、用户名的长度约束。该接口属于用户管理能力，沿用用户路由现有的认证与权限依赖。

### 创建与修改

创建和修改用户时，后端在持久化前调用同一领域服务复核。结果不一致时：

- 不拒绝请求；
- 不修改用户提交的用户名；
- 写入结构化 warning 日志，仅包含操作类型和目标用户 ID（修改时）；遵循项目隐私约定，不记录姓名、提交用户名或建议用户名。

现有响应结构保持不变。数据库用户名唯一约束、现有字段校验及异常处理继续生效。

## 前端设计

### 表单顺序与状态

姓名字段移动到用户名字段之前。用户表单维护以下局部状态：

- 用户是否已手动编辑用户名；
- 最近一次校验对应的姓名和用户名；
- 建议用户名与一致性；
- 校验加载及失败状态。

每次打开抽屉时重置这些状态，避免新增和编辑会话相互污染。

### 新增用户

姓名变化后约 300ms 防抖调用校验接口。用户尚未手动编辑用户名时，将响应中的建议用户名自动填入用户名字段。自动写入不应被标记为手动编辑。

用户一旦直接编辑用户名，当前表单会话中后续姓名变化只重新校验和更新提示，不再覆盖用户名。

### 编辑用户

编辑表单始终保留已有用户名，不做自动覆盖。姓名或用户名发生变化后调用校验接口并更新提示。

### 警告与提交

当 `consistent` 为 `false` 时，在用户名字段下显示黄色警告及建议值，例如：

> 用户名与姓名拼音不一致，建议使用 zhangsan。

点击提交时取消尚未执行的防抖，并以当前姓名和用户名立即调用校验接口，避免使用过期结果：

- 一致时直接执行原有提交逻辑。
- 不一致时弹出确认框，展示当前用户名和建议用户名，提供“返回修改”和“仍然提交”。
- 选择“返回修改”时保留表单内容并聚焦用户名字段。
- 选择“仍然提交”时按原值执行创建或修改。
- 校验接口失败时提示“暂时无法校验姓名拼音”，并提供返回修改或仍然提交，避免校验服务故障阻断用户管理。

校验请求须防止竞态：响应只有在其姓名和用户名仍与当前表单值相同时才可更新界面，较早请求的迟到响应必须被忽略。

所有新增文案同时提供中文和英文翻译。

## 错误处理与边界

- 空姓名或未通过现有姓名规则时不发起拼音校验，由表单原有校验提示处理。
- 自动生成的用户名仍须通过现有用户名格式及长度规则；自动建议不绕过这些规则。
- 用户名唯一性冲突继续由现有创建或修改接口返回，不在拼音校验接口中查询数据库。
- 校验接口超时或失败不清空用户已输入的用户名，也不使用过期建议值。
- 多音字默认结果不正确属于可预期场景，用户可手动修改并确认提交。

## 测试方案

### 后端

- 姓名转拼音：中文、混合英文、大小写、空白和姓名分隔符。
- 多音字使用拼音库默认结果，并将测试固定为所选库的明确输出。
- 精确一致以及大小写、数字后缀、下划线等不一致情况。
- 校验接口的响应结构、字段长度校验、认证及权限要求。
- 创建和修改时，不一致用户名仍能保存且产生 warning 日志。
- 一致用户名正常保存且不产生不一致 warning。

### 前端

- 姓名字段位于用户名字段之前。
- 新建时输入姓名自动填入建议用户名。
- 用户手动编辑用户名后，姓名变化不再覆盖用户名。
- 编辑时不覆盖已有用户名。
- 一致时不显示警告并直接提交。
- 不一致时显示建议值并弹出二次确认。
- “返回修改”不提交，“仍然提交”正常保存。
- 接口失败时提示失败，但允许确认后提交。
- 多个校验请求乱序返回时只接受与当前输入匹配的结果。
- 关闭并重新打开抽屉后，手动编辑标记和校验状态已重置。

## 验收标准

1. 所有用户新增和编辑操作使用后端提供的同一套姓名拼音规则。
2. 新增表单先填写姓名，并在用户未手动修改用户名时自动填入全拼建议。
3. 编辑表单不会自动覆盖已有用户名。
4. 用户名与建议全拼不完全一致时，字段旁和提交前均有明确警告。
5. 用户确认后可以原样保存不一致的用户名，系统不自动改写。
6. 绕过前端调用创建或修改接口时，不一致仍不阻断保存，并留下结构化 warning 日志。
7. 拼音校验服务故障不会阻断用户在二次确认后提交。

## 非目标

- 不建立或维护多音字、少数民族姓名或个人读音词典。
- 不自动解决重名用户名或添加数字后缀。
- 不修改现有用户名唯一性及格式规则。
- 不批量修复历史用户数据。
- 不在登录或用户列表查询流程中执行拼音校验。
