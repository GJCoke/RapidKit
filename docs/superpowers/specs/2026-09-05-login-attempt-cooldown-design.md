# 登录失败次数过多倒计时设计

## 背景与目标

当前同一用户名连续登录失败达到上限后，系统只提示“账号已被锁定”。该文案容易被理解为管理员永久停用账号，也没有告诉用户何时可以重试。

本功能将提示改为“登录失败次数过多”，展示服务端提供的剩余等待时间，并在登录页实时倒计时。倒计时只改善临时登录限制的反馈，不改变失败计数阈值、限制时长、账号状态或认证安全策略。

## 用户体验

达到失败次数上限后，登录表单显示：

> 登录失败次数过多，请在 04:59 后重试

交互规则：

- 剩余时间每秒更新。
- 小于一小时时使用 `MM:SS`，一小时及以上使用 `HH:MM:SS`。
- 倒计时期间禁用登录按钮；点击按钮或按回车都不得再次发送登录请求。
- 倒计时归零后清除提示并恢复登录按钮。
- 普通凭据错误、待激活账号和停用账号不启动倒计时。
- 页面刷新后不从浏览器恢复倒计时；再次提交时以后端返回的最新 Redis TTL 为准。

## 后端设计

### 错误响应

保留现有业务状态码 `14010`（内部枚举名可继续使用 `ACCOUNT_LOCKED`），面向用户的中英文文案调整为：

- 中文：`登录失败次数过多`
- 英文：`Too many failed login attempts`

异常响应通过 `AppException.data` 返回结构化信息：

```json
{
  "code": 14010,
  "message": "登录失败次数过多",
  "data": {
    "retryAfterSeconds": 287
  }
}
```

不把时间拼进后端消息，避免静态文本过期，并保留前端国际化和格式化能力。

### 剩余时间来源

认证服务确认失败次数已达到配置阈值后，对当前用户名对应的 Redis 计数键调用 `TTL`。返回规则：

- TTL 为正整数时原样返回。
- TTL 为 `0`、`-1`、`-2` 或其他异常值时返回 1 秒。

后端只在已经进入限制状态后返回剩余时间。未达到阈值的失败请求继续返回通用认证失败，避免通过错误差异泄露账号是否存在。

## 前端设计

### 错误数据传递

当前请求层会统一展示业务错误，认证 Store 只拿到 `error`。本功能需要让登录流程识别状态码 `14010` 及其 `data.retryAfterSeconds`，但不应让组件依赖 Axios 原始对象。

登录 Store 将登录结果建模为明确的结果类型：成功、普通失败或临时限制。临时限制结果包含经过边界校正的 `retryAfterSeconds`。表单只消费该结果，不解析网络层内部结构。

请求层仍负责普通错误提示；对状态码 `14010` 应避免同时弹出全局错误和表单倒计时提示，防止重复反馈。

### 倒计时状态

复用 `@rapidkit/hooks` 已有的 `useCountDown`，不另写计时器。登录表单维护服务端限制状态：

- 收到临时限制结果时，以 `retryAfterSeconds` 启动倒计时。
- 根据剩余秒数计算 `MM:SS` 或 `HH:MM:SS` 文本。
- 倒计时期间，登录按钮的禁用状态与提交函数入口同时设防。
- 倒计时归零时清除限制提示。
- 组件卸载时由倒计时 hook 停止内部计时资源。

提示使用表单内联警告样式，放在密码框与操作区之间，使用户不依赖短暂的全局消息也能看到剩余时间。

## 错误与边界处理

- 响应数据缺失、非数字、非有限值或小于 1 时，前端按 1 秒处理。
- 服务端 Redis TTL 查询失败时不扩展新的认证故障；按 1 秒响应临时限制。
- 倒计时只是客户端反馈，真正是否允许登录始终以后端 Redis 状态为准。
- 用户修改用户名不会提前清除当前倒计时，避免通过切换输入绕过当前页面的请求抑制；倒计时结束后可使用任意用户名重试。
- 不在浏览器存储用户名对应的限制结束时间，避免增加个人信息或跨会话状态。

## 测试方案

### 后端

- 达到失败阈值时读取当前计数键 TTL。
- 正 TTL 通过 `retryAfterSeconds` 返回。
- TTL 为 `0`、`-1`、`-2` 时降级为 1。
- 错误响应保持状态码 `14010`，并使用新的中英文文案键值。
- 未达到阈值时仍返回通用认证失败。
- 不改变首次失败时设置限制 TTL 的现有行为。

### 前端

- 临时限制响应被 Store 转换为包含秒数的明确结果。
- 普通失败、待激活和停用错误不会启动倒计时。
- `287` 秒格式化为 `04:47`，`3887` 秒格式化为 `01:04:47`。
- 倒计时逐秒减少并在零时清除提示。
- 倒计时期间按钮点击和回车提交均不调用登录接口。
- 全局错误处理不会与内联临时限制提示重复展示。
- 组件卸载时停止倒计时。

## 验收标准

1. 用户不再看到含糊的“账号已被锁定”，而是“登录失败次数过多”。
2. 提示包含准确、动态更新的剩余等待时间。
3. 等待期间登录按钮不可用，提交入口不会产生新请求。
4. 倒计时结束后表单自动恢复可提交状态。
5. 刷新或篡改前端倒计时不能绕过后端限制。
6. 其他登录错误行为不受影响。

## 非目标

- 不修改登录最大失败次数或限制时长配置。
- 不引入按 IP、设备或全局维度的额外限流。
- 不提供管理员手动解除临时限制的功能。
- 不持久化前端倒计时。
- 不改变账号待激活或停用状态的提示。
