# AppAvatar 文字头像与顶部用户菜单重构设计

## 背景

`apps/frontend` 当前没有可复用的业务头像组件。部分页面直接使用 Naive UI 的 `NAvatar`，顶部的 `UserAvatar` 组件则同时负责登录入口、用户信息展示、下拉菜单和退出操作。组件名称与实际职责不一致，也无法统一复用头像降级、字符提取和颜色规则。

本次设计新增通用 `AppAvatar`，并将顶部 `UserAvatar` 重构为职责明确的 `UserMenu`。后端继续只保存头像 URL，不新增头像颜色字段，也不生成文字头像图片。

## 目标

- 头像 URL 可用时显示图片。
- URL 为空或加载失败时显示文字头像。
- 中文名称最多显示末尾两个汉字。
- 英文名称最多显示两个大写字符，多单词优先显示前两个单词的首字母。
- 文字头像具有飞书风格的稳定底色和柔和斜向白色高光。
- 同一用户长期显示相同颜色，用户改名不改变颜色。
- 顶部用户区域使用新的通用头像，同时保持现有登录、下拉菜单和退出行为。

## 非目标

- 不新增数据库字段或迁移。
- 不由服务器生成或存储文字头像图片。
- 不允许用户在本次功能中手动选择头像颜色。
- 不在本次重构中改造所有现有头像使用位置；通用组件完成后可按需逐步接入。

## 组件结构

### `AppAvatar`

位置：`apps/frontend/src/components/common/app-avatar.vue`

该组件只负责头像呈现，不包含用户菜单、登录、路由或退出行为。

建议接口：

```ts
interface AppAvatarProps {
  src?: string | null
  name?: string | null
  seed?: string | number | null
  size?: number
  round?: boolean
  alt?: string
}
```

默认值：

- `size`: `40`
- `round`: `true`
- `alt`: 使用规范化后的 `name`；名称为空时使用本地化的通用头像说明

显示顺序：

1. `src` 非空且图片加载成功时显示图片。
2. `src` 为空或图片加载失败时显示文字头像。
3. 名称无法生成文字时显示通用用户图标。

每个组件实例独立记录当前 URL 的加载失败状态。`src` 变化时清除旧失败状态并尝试加载新 URL。

### `UserMenu`

将现有文件：

`apps/frontend/src/layouts/modules/global-header/components/user-avatar.vue`

重命名为：

`apps/frontend/src/layouts/modules/global-header/components/user-menu.vue`

组件名改为 `UserMenu`。它继续负责：

- 未登录时显示登录/注册入口。
- 已登录时显示用户信息并作为下拉菜单触发器。
- 构建下拉菜单选项。
- 执行退出操作和相关路由行为。

已登录状态下，使用：

```vue
<AppAvatar
  :src="authStore.userInfo.avatar"
  :name="authStore.userInfo.nickname || authStore.userInfo.name"
  :seed="authStore.userInfo.id"
  :size="32"
/>
```

顶部 `global-header/index.vue` 改为导入并渲染 `UserMenu`。本次重构不改变现有登录和退出语义。

## 名称字符规则

字符规则由 `apps/frontend/src/utils/avatar.ts` 中的纯函数实现，避免组件内混入字符串处理细节。

处理顺序：

1. 对名称执行 Unicode 安全的首尾空白清理，并合并连续空白。
2. 如果名称包含汉字，提取名称中的汉字序列并取最后两个；只有一个汉字时显示一个。
3. 如果名称不含汉字但包含多个以空白分隔的词，取前两个有效词的首个 Unicode 可见字符并转为大写。
4. 如果只有一个词，取前两个 Unicode 可见字符并转为大写。
5. 混合数字、符号或 Emoji 时按 Unicode code point 处理，最终最多输出两个可见字符。
6. 结果为空时由组件显示通用用户图标。

示例：

| 输入 | 输出 |
| --- | --- |
| `王小明` | `小明` |
| `李雷` | `李雷` |
| `John Doe` | `JD` |
| `Alice Smith Cooper` | `AS` |
| `Alexander` | `AL` |

## 颜色持久化

正式用户使用不可变用户 ID 作为 `seed`。颜色计算过程为：

```text
String(seed) -> FNV-1a 32 位哈希 -> hash % AVATAR_PALETTE_V1.length
```

建议锁定第一版色板：

```ts
export const AVATAR_PALETTE_V1 = [
  "#245BDB",
  "#5B4BDB",
  "#7C3AED",
  "#C2416C",
  "#D14343",
  "#C76B00",
  "#16835D",
  "#087F8C",
] as const
```

持久化约束：

- 不使用 `Math.random()`。
- 正式用户必须传不可变 ID，不以名称作为主种子。
- `seed` 缺失时才降级使用规范化名称。
- `seed` 和名称都为空时使用固定的灰蓝色默认值。
- `AVATAR_PALETTE_V1` 发布后不修改颜色或排列顺序。
- 后续视觉升级新增版本化色板，不覆盖 V1。
- FNV-1a 实现通过固定输入输出测试锁定，防止无意改变映射。

这一方案无需新增后端字段。只要用户 ID、哈希算法和 V1 色板不变，用户改名、刷新页面或更换浏览器后仍会得到相同颜色。未来其他客户端需要完全一致时，应复用同一算法和色板规范。

## 视觉样式

文字头像使用白色文字、稳定底色和已确认的柔和斜向白色高光：

```css
background:
  linear-gradient(
    145deg,
    rgb(255 255 255 / 42%) 0%,
    rgb(255 255 255 / 10%) 43%,
    rgb(255 255 255 / 0%) 72%
  ),
  var(--avatar-color);
```

组件增加轻微的顶部内高光，但不使用明显投影。字体尺寸按头像尺寸成比例计算，并设置合理上下限，保证常用小尺寸头像仍清晰可辨。圆形裁剪由 `round` 控制。

渐变属于组件统一样式，不属于用户数据，不发送到后端。

## 可访问性

- 图片使用显式 `alt`，默认来源于 `name`。
- 文字头像容器提供对应的 `aria-label`。
- 降级图标是辅助视觉内容，不重复朗读。
- 色板使用相对较深的底色，确保白色文字具有清晰对比度。
- 头像本身不默认承担按钮语义；交互语义由 `UserMenu` 等调用方提供。

## 错误与降级

- 图片 URL 请求失败时，在当前实例中切换为文字头像。
- 更换 `src` 后重新尝试图片加载，不沿用旧 URL 的失败状态。
- 名称为空时显示通用用户图标。
- `seed` 为空时使用名称计算颜色；名称也为空时使用固定默认颜色。
- 字符提取和哈希函数对异常输入返回安全的确定性结果，不向调用方抛出异常。

## 测试

### `avatar.ts` 单元测试

- 中文名称取最后两个汉字。
- 一个汉字能够正常显示。
- 英文多单词取前两个单词首字母。
- 英文单词取前两个字符并大写。
- 连续空格、中英文混合、数字、符号、Emoji 和空名称均有确定结果且不抛错。
- 同一 `seed` 始终映射至同一色板键。
- ID 不变而名称变化时颜色不变。
- 固定测试向量锁定 FNV-1a 输出和 V1 色板映射。

### `AppAvatar` 组件测试

- URL 有效时显示图片。
- URL 缺失时显示文字头像。
- 图片触发加载错误后显示文字头像。
- `src` 改变后重新尝试图片加载。
- 名称为空时显示通用图标。
- `size`、`round`、`alt` 正确作用于渲染结果。

### 顶部集成验证

- 未登录状态仍显示登录/注册按钮。
- 已登录状态显示 `AppAvatar` 和用户名称。
- `avatar`、`nickname || name` 和 `id` 正确传入头像组件。
- 下拉菜单能够打开，退出确认和退出流程保持不变。

## 实施边界

本次实施包含通用组件、头像工具函数及其测试，并重构顶部用户组件接入 `AppAvatar`。其他页面中的直接 `NAvatar` 用法不在本次范围内，后续可逐步替换，避免一次变更扩散到聊天等独立业务模块。
