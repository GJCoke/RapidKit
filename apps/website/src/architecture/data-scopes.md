# 声明式数据范围与字段规则

资源通过 `ResourceDef.data_scopes` 声明数据范围，通过 `field_groups` 声明受控字段组。
角色对每个资源单选范围，对每个字段组单选可见、脱敏或隐藏；未配置时为全部、可见。
多个角色的数据范围取并集，字段状态取最宽松值。超级管理员不受限制。

## 开发约束

- `Require(code)` 把主资源的条件绑定到请求会话。查询、统计、关联和 ORM 删除自动过滤该模型；关联带出的其他模型不附加行范围。
- 新增和修改应使用同一请求会话里的 ORM 对象；flush 时检查受控字段写入，并复查写入结果是否仍在范围内。异常必须回滚事务。
- 批量 ORM UPDATE 不得修改范围条件引用的列或受控字段，运行时会拒绝这些操作；改用加载对象后赋值、flush 的方式。`BaseCRUD.update_all` 同样受此约束。
- 不得用原生 SQL、Core Table UPDATE 或另建会话访问请求中的受控模型；这些路径不提供同样的范围保证。`Session.get()` 命中 identity map 时也不会重新过滤；查询使用 `BaseCRUD.get()` 或 SELECT。
- 从 ORM 对象构造 `BaseResponse` / `BaseSchema`，序列化会按来源模型处理字段，嵌套响应同样生效。手工构造的 dict 应经 `scope.serialize(data, Model)` 处理。
- `unscoped(session)` 只用于必须查看全量数据的内部检查，例如部门是否仍有子部门；它不会关闭字段写入保护。`pnpm report:unscoped` 输出全部使用位置供审查。
- 字段规则按请求隔离。任务、启动脚本和未绑定范围的新会话不会自动使用请求规则。

角色保存会去掉全部、可见的默认值。功能包保留显式选择的全部、可见，应用时可清除角色原有限制；合并模式按资源覆盖范围、按资源及字段组覆盖字段状态，未设置项保持原值。替换模式使用功能包的完整授权集合。
